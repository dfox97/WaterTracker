# CLAUDE.md

This file provides guidance to Claude Code when working with code in this repository.

## Project

**WaterTracker** — a full-stack water consumption tracker.

Authenticated users can register, log in, and manage their daily water intake records.

Built with:

- .NET 10
- Blazor Server
- ASP.NET Core Identity
- EF Core
- SQLite
- FluentValidation
- xUnit

The project should prioritise simple, maintainable, testable code over unnecessary abstraction.

## Commands

```bash
dotnet restore
dotnet build
dotnet run                          # http://localhost:5016
dotnet watch                        # hot reload

dotnet test
dotnet test --filter FullyQualifiedName~WaterIntakeServiceTests

dotnet ef migrations add <Name>
dotnet ef database update
```

OpenAPI doc at `/openapi/v1.json` in development.

## Dependency rule

`Endpoints` and `.razor` pages call `IWaterIntakeService`. Only the service touches `ApplicationDbContext`. Validators are pure.

```
UI (Tracker.razor)  →  IWaterIntakeService  →  ApplicationDbContext
API Endpoint        →  IWaterIntakeService  →  ApplicationDbContext
```

Auth pages (`Components/Account/Pages/Login.razor`, `Register.razor`, `Manage/…`) are generated by the Identity scaffold and are not part of the `Features/` layer.

## SOLID rules

- `IWaterIntakeService` is the seam (DIP). The service is what tests target.
- Service has one job: water-intake use cases. No HTTP, no rendering. Endpoints and Razor pages stay thin.
- FluentValidation validators live in their own classes — testable, swappable, no validation logic in the service.
- **No `IWaterIntakeRepository`.** Inject `ApplicationDbContext` directly into the service.
- **No `IClock`.** Use `DateTimeOffset.UtcNow` directly. Reach for `TimeProvider` (.NET 8+) if a test ever needs fake time.

## Auth

- Cookie auth via Identity (`IdentityConstants.ApplicationScheme`).
- `Components/Routes.razor` wraps every route in `AuthorizeRouteView` — **new pages are auth-required by default**.
- API endpoints: `app.MapGroup("/api/intake").RequireAuthorization()`. Resolve current user with `ClaimsPrincipal.FindFirstValue(ClaimTypes.NameIdentifier)`.
- `SignIn.RequireConfirmedAccount = true` is on with `IdentityNoOpEmailSender`, so confirmation emails don't actually send. In dev, grab the URL from the response or relax the option.

## Data

- **SQLite** (`Data Source=watertracker.db`) — cross-platform, no LocalDB. `Program.cs` was scaffolded with `UseSqlServer` — swap to `UseSqlite` before first run.
- One DbContext: `ApplicationDbContext : IdentityDbContext<ApplicationUser>`. Add domain `DbSet<T>`s here; don't introduce a second context.
- `WaterIntakeEntry` { `Id: Guid`, `UserId: string` (FK → AspNetUsers), `AmountMl: int`, `RecordedAt: DateTimeOffset`, `Notes: string?` }.
- `ApplicationUser : IdentityUser` — extend with profile fields here, not parallel tables.
- Migrations regenerated under the SQLite provider.

## Testing

- `WaterTracker.Tests`: xUnit + FluentAssertions + NSubstitute.
- Service tests use **SQLite in-memory** (`Data Source=:memory:`, open the connection per test class, `EnsureCreated`). Closer to real SQL than `UseInMemoryDatabase`, and you usually don't need to mock `DbContext` at all.
- Validator tests instantiate the validator directly — no DI needed.
- Endpoint tests use `WebApplicationFactory<Program>` (add `public partial class Program;` at the bottom of `Program.cs`).
- Razor component tests (bUnit) deferred — service-level tests carry the SOLID/testability story.

## Conventions

- `Nullable` and `ImplicitUsings` are on.
- All IO methods are `Async` and take `CancellationToken`.
- DTOs are `record`s with `required` members; mapping is hand-written (no AutoMapper).
- Validation is FluentValidation, not DataAnnotations.
- `BlazorDisableThrowNavigationException=true` is set — don't try/catch around `NavigationManager.NavigateTo`.
- User secrets configured (`UserSecretsId` in csproj) — `dotnet user-secrets set` for local secrets, never `appsettings.json`.

## C# 14 style (models default to older patterns — enforce these)

- **Primary constructors** on every class/service. No explicit constructor body + private field boilerplate.
  ```csharp
  public class WaterIntakeService(ApplicationDbContext db) : IWaterIntakeService { }
  ```
- **Collection expressions** instead of `new List<T> { }` or `new[] { }`.
  ```csharp
  List<string> tags = [a, b, c];
  ```
- **`required` members** on records and entities to catch missing init at compile time.
  ```csharp
  public record CreateIntakeRequest { public required int AmountMl { get; init; } }
  ```
- **File-scoped namespaces** everywhere — no wrapping braces.
  ```csharp
  namespace WaterTracker.Features.WaterIntake;
  ```
